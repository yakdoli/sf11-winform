DomainGridDataControl   

 

DomainGridDataControl lets users to get data form DomainDataSource. DomainGridDataControl depends on GridDataControl and all the properties in GridDataControl are supported in DomainGridDataControl except Nested Grids.  This control is useful while developing a RIA application which uses DomianDataSource as input collection.

 

Prerequisites

Development Environments

 Silverlight

.NET Framework versions

 3.5, 4.0

Mandatory installation

 WCF RIA services 2008 or 2010

 

Creating a DomainGridDataControl Application

1.   Create a Silverlight application with RIA service enabled and with an ASP.NET web project.

 

 

Figure 12: Silverlight Application

 

2.   Add a Database file to the web project.

 


Figure 13: Added Database File to the Web Project

 

3.   Add a Data Model to your application. It can be a LINQ to SQL data model, an Entity Framework Data Model, or any other data model.

 

Figure 14: Added Data Model

4.   Add a new Domain Service.

5.   Add a new Item to the web project, and select the Domain Service template.

 

 

Figure 16: Domain Service Class

 

 

6.   After you add Domain Service, the New Domain Service Class Dialog is shown.

7.   Select the Data Context, the entities you want to expose and whether you want to allow editing.

8.   Click OK.

Figure 17: New Domain Service

 

 

 

9.   In the Silverlight application add references to System.Windows.Controls.Data and to RIA related assemblies.

10.  Add a DomainDataSource control in XAML.

11.  Drag and drop DomainDataGrid into the designer surface. 

12.  Set RIASource property to DomainDatasource.

 

Create a DomainGridDataControl Application, by using the following code.

 

[XAML]

 

<UserControl x:Class="Syncfusion.Grid.Silverlight.Samples.DomainDataSourceDemo"

     xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"

    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"

    xmlns:data="clr-namespace:System.Windows.Controls;assembly=System.Windows.Controls.Data"

    xmlns:riaData="clr-namespace:System.Windows.Data;assembly=System.Windows.Controls.Ria"

    xmlns:ria="clr-namespace:System.Windows.Controls;assembly=System.Windows.Controls.Ria"

    xmlns:my="clr-namespace:Syncfusion.Grid.Silverlight.Samples.Web.Model"

    xmlns:sd="clr-namespace:Syncfusion.Windows.Controls.Grid;assembly=Syncfusion.Grid.Silverlight"

    xmlns:syncfusion="clr-namespace:Syncfusion.Windows.Controls.Grid.Ria;assembly=Syncfusion.Grid.Ria.Silverlight"

    >

    <Grid x:Name="LayoutRoot">

        <Grid.RowDefinitions>

            <RowDefinition Height="Auto">

            </RowDefinition>

            <RowDefinition Height="*">

            </RowDefinition>

            <RowDefinition Height="Auto">

            </RowDefinition>

            <RowDefinition Height="40"></RowDefinition>

        </Grid.RowDefinitions>

        <ria:DomainDataSource Grid.Row="0" x:Name="dds" QueryName="GetOrders" AutoLoad="True">

            <ria:DomainDataSource.DomainContext>

                <my:NorthwindContext></my:NorthwindContext>

            </ria:DomainDataSource.DomainContext>         

        </ria:DomainDataSource>

        <syncfusion:DomainGridDataControl VisualStyle="ShinyBlue"   x:Name="grid" Grid.Row="1" AutoPopulateColumns="True" AutoPopulateRelations="False" ShowGroupDropArea="True"   RIASource="{Binding ElementName=dds}" LoadingText="Loading..." >

           

 

        </syncfusion:DomainGridDataControl>

        <data:DataPager x:Name="pager" Grid.Row="2" Source="{Binding Data, ElementName=dds}" PageSize="10" IsTotalItemCountFixed="True"></data:DataPager>

        <Button x:Name="Submit" Grid.Row="4" Content="SUBMIT" VerticalAlignment="Center" HorizontalAlignment="Center" Width="200"></Button>

    </Grid>

</UserControl>

Feature Summary

Sorting – Click on the column header to trigger Sorting.

Note: Sorting happens in the server side and the data is retrieved and populated in the client side.

 

Filtering – Enter appropriate data in the Filter pane to trigger Filtering.

Note: Filtering also occurs on the server side and the data is populated on the client side.

Filter pane is disabled immediately after entering appropriate data in the Filter pane till the data gets populated.

 

Grouping - Dragging and Dropping columns in GroupDropArea triggers Grouping.

Note: Grouping is based on client side data.

 

 Paging - Paging is supported by adding a DataPager control in XAML as shown in above sample XAML code.

Note: Paging occurs in the server side and the data is populated in the client side.
